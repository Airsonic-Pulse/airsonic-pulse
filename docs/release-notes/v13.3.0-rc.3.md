# Airsonic-Pulse v13.3.0-rc.3

## Upgrade notes

Third release candidate of the 13.3 line. It differs from rc.2 only in bundled library versions.

This candidate updates five bundled libraries to releases that carry security fixes, some of them rated critical by their maintainers (#415): Apache CXF 4.1.7, Bouncy Castle 1.85, jsoup 1.23.2, junrar 7.6.1 and Guava 33.7.2. Everyone running 13.2.1 or an earlier 13.3.0 candidate should plan to upgrade; the 13.3.0 final follows within days if nothing blocking is reported. The WAR reports 13.3.0-SNAPSHOT on the login page; that is expected for release candidates and changes at the final.

- Two Liquibase changesets run on first start (liquibase/13.3): `lyrics.source_last_modified`, nullable, used to invalidate the lyrics cache when a sidecar file or tag changes (#281); and `play_queue_file.position`, with a backfill of existing saved queues from id order (#214). Back up the database before upgrading. Downgrading to 13.2.x after these changesets have run is not supported.
- The first scan after upgrading may remove genres that no longer appear on any file (#319). Album folder metadata follows retagged tracks on any scan, and search no longer returns albums or artists that a scan has marked as gone (#405).
- General Settings gains fields for the ReplayGain fallback (#252) and the scan timeouts (#208); existing property values are honoured.
- Saving General Settings no longer re-imports playlists unless the playlist folder changed (#382); clearing the folder now stops its watcher (#394).

## Summary

Security: five bundled libraries updated to patched releases (#415).

Fixes users will notice: Play all on the Starred page (#371) and playing a playlist entry whose file went missing (#402) no longer fail with an UnsupportedOperationException; play-queue WebSocket sessions no longer create ownerless players (#354); the lyrics cache now notices changed sidecar files and tags (#281); genres no longer linger after their last file is retagged or removed (#319); a changed album artist shows in the album folder and in search after one scan (#405); three null-duration crashes in play-count, XSPF and Sonos paths are guarded (#322); shuffle play of a folder picks its songs with one database query instead of walking the whole subtree (#351).

Hardening: count and size parameters are clamped, including cover-art size which could request an unbounded image (#286); podcast refresh persists episodes on the refresh thread instead of parallel workers (#353); the apiKey audit log distinguishes unknown, disabled and expired keys (#284).

Internal: remaining commons-lang 2.x usages migrated to lang3 (#180); a build-time check against mutation of immutable list returns (#302); an i18n completeness test with 32 drifted bundle keys fixed (#299); test-fixture hygiene and two test classes that had never run (#266, #395); the unused /ext controller prefix dropped (#335); a parser-strategy decision record added.

New in rc.3: the library updates from #415. No functional change from rc.2; the #405 fix is as shipped in rc.2.

## Known issues

- The bundled UPnP/DLNA library (cling-core 2.0.1) has a published denial-of-service advisory (CVE-2020-23622) for which no fixed version exists. DLNA is off by default; leave it off unless you need it.
- One advisory rated medium remains open for Apache HttpClient 5, which is used only for the outbound check for new versions (#416).
