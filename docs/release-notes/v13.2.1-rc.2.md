# Airsonic-Pulse v13.2.1-rc.2
## Upgrade notes

Patch release for 13.2.0. No database schema changes: upgrading from 13.2.0 or 13.2.1-rc.1 needs no migration, and rolling back to 13.2.0 is safe.

After upgrading, the first library scan is intentionally slow: it is the one-time metadata backfill that 13.2.0 introduced. Every scan after it is incremental again. On 13.2.0 that first scan repeated forever; that is the bug fixed here.

## Summary of changes since v13.2.0

Restores every stream flow that uses a server-issued JWT URL: external players (m3u), shares, UPnP/DLNA, Sonos and cast. A duplicate `/ext/stream` mapping introduced in 13.1.0 made Spring reject the request with an ambiguous-handler error (#325, PR #334).

Restores full-library enumeration through search3 with an empty query, used by clients such as Symfonium to sync. 13.2.0 clamped the offset to 500 on that path along with the count (#333, PR #337).

Fixes the scan regression (#331): 13.2.0's one-time rescan never wrote the new metadata version back, so every scan after an upgrade re-parsed the entire library (#341). This also drove the connection-pool exhaustion reported on folder shuffle and DSub radio (#323): the shuffle path re-validates every file under the folder, and on an upgraded library each of those turned into a tag re-read and a database write.

Also carries three small fixes from the 13.3 line: MediaFile.equals no longer throws on a null folder or start position (#216), CUE and audiobook indexing no longer fails on a null base duration (#289), MP4 ReplayGain atoms are matched case-insensitively (#251).

## New in rc.2

The scan fix (#341). Everything else is unchanged from rc.1.

## Known issues

Podcast channel deletion failing on MariaDB (#330) is under investigation. If you hit the pool exhaustion from #323: upgrade, let one full scan complete, then retry; report on the issue if it persists.
